# Agent Pedagogical Experiment Design

## Purpose

Pedagogical experiment design adds a small semantic layer above the
Exploration Agent's existing ScenarioSpec planner. It lets a learner ask a
testable question and receive a reversible proposal that explains what will
change, what will stay fixed, and which runtime evidence to watch.

The design is a proposal, not an executable plan:

```text
learner question
  -> bounded ExplorationDesign
  -> deterministic scenario planner
  -> detached preflight and exact fidelity
  -> explicit execution
  -> comparison/evidence/thread history
```

The Agent never emits observations, operations, ScenarioSpec JSON, or metric
values as authority.

## Contract

`src/core/exploration/pedagogicalExperiment.js` owns the versioned contract.
V1 supports four goals:

- `class-overlap`
- `train-test-support-shift`
- `observation-noise`
- `outlier-sensitivity`

Each goal has one registered intervention and evidence intent. Validation is
strict, bounded, and independent of the provider schema. A prediction is an
optional learner input; it is not a result or a causal claim.

## Deterministic compilation

`scenarioPlanner.js` compiles a valid design against the current session.
Recipe Worlds use the existing `PATCH_WORLD_RECIPE` and regeneration
operations. The first supported KNN path moves one group toward another for
class-overlap; test-support shift uses split-specific test transforms; noise
and outlier designs use the existing bounded recipe patch variants. Legacy
linear-regression Worlds reuse the existing registered intent operations where
they are supported.

The planner prefers the current World. It rejects a goal when the current task,
recipe, model, or registered operation capabilities cannot represent it. Every
proposal goes through the existing ScenarioSpec validator, detached preflight,
and exact fidelity assessment before it is shown as executable.

## Evidence and follow-ups

`pedagogicalEvidence.js` is a projection of the post-execution comparison and
runtime observables. Accuracy is used for classification; MSE is used for
regression. Coverage mismatch is included for support-shift experiments.
Values are never recomputed in React or generated by the Agent. Up to two
follow-up designs are offered only after they themselves pass current
capability planning and detached preflight.

## Prediction and Threads

When a learner enters an optional prediction and an Exploration Thread is
active, the existing prediction and experiment entry operations record it.
No new Thread entry kind or scoring system is introduced.

## Provider boundary and fallback

The AI interpreter receives the bounded semantic context already used by the
Exploration Agent, plus the supported goal vocabulary. A strict structured
`experimentDesign` response is canonicalized and validated locally before
planning. Provider failure falls back to the existing local speech-act rules
for obvious overlap, support-shift, noise, and outlier questions.

## Limitations

V1 does not add World Composer primitives, MLP `applyWorld`, parameter sweeps,
automatic execution, causal explanation, or a full Composer editor. World
Composer remains the deterministic infrastructure; this slice only chooses a
small set of pedagogical questions that current operations can execute
truthfully.
